### 方案二（用户当场否决"实际最小值"，改为固定起始层级）
- 用户原话：每层按摆满算层级是固定的，每层有固定起始层级（可写死），**起始层级即影子层级**，牌从起始层级往上排。
- 落地：
  - `SortingOrderLayerStep` **20 → 256**；`SortingOrderEliminating` **380 → 3000**。
  - 新增 `GetLayerSortingOrderStart(layer) = SortingOrderBase + layer * SortingOrderLayerStep`。
  - 牌层级 = `起始 + 1 + (maxCoordX - CoordX) * 16 + CoordY`（`+1` 是关键，否则偏移为 0 的牌与影子同层级）。
  - 影子层级 = `起始`。`GetLayerMinimumSortingOrder` 已删除。
- 实测数据支撑：998 关 rows 1~7、cols 2~6、层数 1~4、每关 2~102 张；**层内最大偏移 202**（关卡 140：maxCoordX=12, coordX=0, coordY=10）。Step=256 留 52 余量，可容纳 rows=8/cols=7 扩展（236）。
- 998 关全量仿真结果：影子被牌覆盖 0 例、层间交错 0 例、全局最大牌层级 1040 < 消除层级 3000。各层区间：L0 影子120/牌121-323；L1 影子376/牌379-575；L2 影子632/牌667-801；L3 影子888/牌940-1040。

## 导入 MahjongBlastGoldSides 后编译报错（UIParticle 重复导入）
- 现象：Editor.log 里一堆 `error CS1061 'UIParticle' does not contain a definition for 'groupId'/'canRender'/'scale3DForCalc'/'parentScale'/'autoScalingMode'/'m_AnimatableProperties'`、`error CS0122 'UIParticleUpdater' is inaccessible`、`error CS0234 'UIParticleInternal' does not exist in namespace 'Coffee'`。
- 根因（两层）：
  1. 导入时**把新版 UIParticle 的源码覆盖进了 `Assets/ParticleEffectForUGUI-3.3.13/Scripts/`**（UIParticle.cs / UIParticleUpdater.cs / AnimatableProperty.cs / Editor / UIAdditive.shader 共 7 个文件，git 显示 M），但**没带 `Internal/` 目录** → 新版 `using Coffee.UIParticleInternal` 找不到 → `Coffee.UIParticle` 程序集编译失败。
  2. 该程序集失败后，`Assembly-CSharp` 编译时用的是**上一次成功编译的旧二进制**（旧版 UIParticle 没有 groupId 等），于是新插件 `ThirdParty/UIParticle/Runtime/UIParticleRenderer.cs`、`UIParticleAttractor.cs` 全部报 CS1061/CS0122。**这些都是级联假象，不是真的 API 不兼容。**
  3. 另外新插件还自带了一份 `ThirdParty/UIParticle`（含 `Coffee.UIParticle.R.dll` + 源码，无 asmdef），与 3.3.13 的 asmdef 程序集重复定义 `Coffee.UIExtensions.UIParticle`。
- 修复：
  1. 把 `Assets/MahjongBlastGoldSides/ThirdParty/UIParticle`（含 meta）**移出工程**备份到 `D:/AA_Mahjong/_backup_uiparticle_20261023/`。
  2. `git checkout -- Assets/ParticleEffectForUGUI-3.3.13/` 恢复到 3.3.13 原版（原版用 `Coffee.UIParticleExtensions` 命名空间，由 Utils/MeshHelper/ModifiedMaterial/CombineInstanceEx/BakingCamera 提供，自洽）。
- 关键结论：**新插件的 2 个 prefab 引用的 UIParticle 脚本 guid 就是 `16f0b0b6d0b7542bfbd20a3e05b04ff1`（3.3.13 的 UIParticle.cs）**，字段也是 3.3.13 的（`m_IsTrail/m_IgnoreCanvasScaler/m_AbsoluteMode/m_Scale3D/m_AnimatableProperties/m_Particles`），所以它**本来就不需要自带 UIParticle**，删掉完全不影响。

- 教训：**导入带第三方依赖的资源包前先查它是否重复携带已有插件**；覆盖前先看 `git status`，Coffee UIParticle 的 guid 是官方固定值，覆盖源码而不带 Internal 目录必然炸。
