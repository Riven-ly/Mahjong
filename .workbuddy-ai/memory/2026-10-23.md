## 为什么 FragmentPreviewCanvas(Clone) 与 Canvas 下同一特效表现不同（只读分析）
- **根因：UI 相机的 orthographicSize 差 192 倍。** 正交相机下 Canvas 的 `lossyScale = 2*orthographicSize/screenHeight`，而 UIParticle 把粒子世界坐标换算成 UI 局部坐标要除以这个 scale。
  - 项目 `Game.unity` 根 Canvas（名字 `Canvas`，GO 581998318，Canvas 581998321）：Screen Space - Camera + **Main Camera(519420031, orthographic=1, orthoSize=5)** + planeDistance=100 + CanvasScaler 1080x1920 **Expand**
  - Demo `FragmentsDemo.unity` 的 FragmentPreviewCanvas：Screen Space - Camera + **Main Camera(772465120, orthographic=1, orthoSize=960)** + planeDistance=1000
  - 1920/10 = **192 倍**尺度差 → 同一特效在项目 Canvas 下会被放大到约 192 倍（速度也同比例失真）。
- **正交相机下 planeDistance 完全无效**（100 vs 1000 不是原因），只有 orthoSize 和屏幕高度决定 Canvas 世界尺度。
- 搬到项目的 `Assets/Prefab/Mahjong/FragmentPreviewCanvas.prefab` 里 Canvas 的 **`m_Camera: {fileID: 0}`（相机引用丢失）**，运行时 Unity 会把 Screen Space - Camera 退化为 Overlay 并警告 → 它的 lossyScale ≈ 1/scaleFactor ≈ 1，反而接近 Demo 的表现。这就是"同一特效在两个 Canvas 下不一样"的直接观感来源。
- 其他次要差异：`matchNewEffect` 的 Canvas 标 `m_RenderMode: 2`（World Space）但它是**嵌套 Canvas，RenderMode 被忽略**，实际继承根 Canvas 的 Screen Space - Camera，只有 `m_OverrideSorting=1` + `m_SortingOrder=2200` 生效（FragmentPreviewCanvas 是 0）。特效 prefab 的 `m_Scale3D = 10`、`m_IgnoreCanvasScaler = 0`、`m_PositionMode = 0`。
- 可行修法：把特效放到**独立的 Screen Space - Overlay 根 Canvas**（SortingOrder 2200，不能嵌套在现有 Canvas 下），Overlay 的 lossyScale ≈ 1，与 Demo 一致；或改 `m_Scale3D`/粒子 size、speed 做 192 倍补偿（速度难调，不推荐）；改 UI 相机 orthoSize 会波及全局 UI，不可取。

用户：「麻将碰撞时牌缩放了是吧，那 CollisionHalfDistance，ReboundOffsetX 值也应该在用的时候乘以缩放」→ 采纳方案 B，且**两个值都折算**。

**最终代码**（`MahjongGameplayView.cs` L955-959）：
```csharp
float boardScale = boardRoot.lossyScale.x / eliminationLayer.lossyScale.x;
Vector2 firstCollisionPosition = centerPosition + Vector2.left * (MahjongViewConfig.CollisionHalfDistance * boardScale);
Vector2 secondCollisionPosition = centerPosition + Vector2.right * (MahjongViewConfig.CollisionHalfDistance * boardScale);
Vector2 firstReboundPosition = firstCollisionPosition + Vector2.left * (MahjongViewConfig.ReboundOffsetX * boardScale);
Vector2 secondReboundPosition = secondCollisionPosition + Vector2.right * (MahjongViewConfig.ReboundOffsetX * boardScale);
```
- `boardScale` = `boardRoot.lossyScale.x / eliminationLayer.lossyScale.x` = 牌在消除层的实际 localScale = s；用 lossyScale 比值而非 `localScale`，父级任何缩放都能抵消。
- `TransitOffsetX` **未折算**（用户只点名这两个值）。
- 效果：碰撞点两牌中心距 = `210 × s`（= 牌局部宽度，边缘相接）；回弹幅度也随牌同比缩放。
